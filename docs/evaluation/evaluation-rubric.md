# 면접 답변 평가 기준 (Evaluation Rubric)

## 개요

면접 질문 유형은 `technical`(기술)과 `personality`(인성)으로 구분되며,
유형에 따라 평가 항목 일부가 달라진다.

> 초기 버전에서는 question_type을 `technical` / `personality`로 제한한다.
> 추후 `experience`, `project`, `company_fit`, `situational` 등으로 확장 가능하다.

---

## 평가 항목 구성

### 공통 항목 (technical / personality 모두 적용)

| 항목              | 설명                  |
|-----------------|---------------------|
| `relevance`     | 질문 의도에 맞는 답변인지      |
| `logic`         | 답변의 구조와 논리적 흐름      |
| `specificity`   | 구체적인 경험/수치/예시 포함 여부 |
| `conciseness`   | 핵심만 간결하게 전달했는지      |
| `clarity`       | 표현이 명확하고 이해하기 쉬운지   |
| `job_relevance` | JD 키워드 및 직무와의 연관성   |

### 기술 질문 전용 (question_type = technical)

| 항목         | 설명                       |
|------------|--------------------------|
| `accuracy` | 기술 개념의 정확성               |
| `depth`    | 기술적 깊이 (트레이드오프, 내부 동작 등) |

### 인성 질문 전용 (question_type = personality)

| 항목             | 설명                 |
|----------------|--------------------|
| `authenticity` | 답변의 진정성 (경험 기반 여부) |
| `growth`       | 성장 가능성 및 회고 역량     |

---

## 항목별 1~5점 기준

### relevance (질문 적합성)

| 점수 | 기준                             |
|----|--------------------------------|
| 1  | 질문과 전혀 관계없는 내용으로 답변함           |
| 2  | 질문 의도를 일부 파악했으나 핵심에서 벗어남       |
| 3  | 질문에 맞게 답변하나 의도를 완전히 충족하지 못함    |
| 4  | 질문 의도에 맞게 핵심 내용을 전달함           |
| 5  | 질문 의도를 정확히 파악하고 기대 이상의 답변을 제공함 |

### logic (논리성)

| 점수 | 기준                                |
|----|-----------------------------------|
| 1  | 답변 흐름이 거의 없고 질문과 무관한 내용이 섞임       |
| 2  | 일부 흐름은 있으나 논리 연결이 약함              |
| 3  | 기본적인 구조는 있으나 근거와 결론 연결이 부족함       |
| 4  | 주장-근거-예시 흐름이 자연스러움                |
| 5  | 답변 구조가 명확하고 면접관이 이해하기 쉬운 흐름으로 전개됨 |

### specificity (구체성)

| 점수 | 기준                                 |
|----|------------------------------------|
| 1  | 추상적인 표현만 있고 구체적인 내용이 전혀 없음         |
| 2  | 구체적인 내용이 있으나 단편적이고 맥락이 부족함         |
| 3  | 일부 구체적인 예시나 경험이 포함되어 있음            |
| 4  | 수치, 기술명, 경험 등 구체적인 근거가 충분히 포함됨     |
| 5  | 상황, 수치, 결과까지 모두 구체적으로 서술하여 신뢰도가 높음 |

### conciseness (간결성)

| 점수 | 기준                        |
|----|---------------------------|
| 1  | 핵심 없이 장황하게 서술하거나 반복이 심함   |
| 2  | 전달하려는 내용은 있으나 불필요한 내용이 많음 |
| 3  | 핵심은 전달되나 군더더기 표현이 일부 있음   |
| 4  | 핵심 위주로 간결하게 전달함           |
| 5  | 필요한 내용만 담아 짧고 명확하게 전달함    |

> conciseness는 LLM 평가 점수 산출 후 음성 분석 기반 penalty 반영하여 `conciseness_final`로 최종 계산한다.

### clarity (명확성)

| 점수 | 기준                           |
|----|------------------------------|
| 1  | 무슨 말인지 이해하기 어려운 표현이 대부분임     |
| 2  | 일부 내용은 전달되나 표현이 모호하거나 혼란스러움  |
| 3  | 대체로 이해할 수 있으나 일부 표현이 불명확함    |
| 4  | 표현이 명확하여 전달 의도를 쉽게 파악할 수 있음  |
| 5  | 전달이 매우 명확하고 면접관이 즉시 이해할 수 있음 |

### job_relevance (직무 연관성)

| 점수 | 기준                              |
|----|---------------------------------|
| 1  | JD 키워드나 직무와 전혀 관련이 없음           |
| 2  | 직무와 연관성이 희박하거나 우연적으로 언급됨        |
| 3  | 직무와 일부 연관성이 있으나 연결이 약함          |
| 4  | JD 키워드나 직무 요구사항과 명확히 연결됨        |
| 5  | 직무 요구사항을 정확히 이해하고 답변에 자연스럽게 녹여냄 |

### accuracy (기술 정확성) — technical 전용

| 점수 | 기준                          |
|----|-----------------------------|
| 1  | 기술 개념에 오류가 많아 신뢰하기 어려움      |
| 2  | 개념의 방향은 맞으나 세부 내용에 오류가 있음   |
| 3  | 대체로 정확하나 일부 개념이 불명확하거나 혼용됨  |
| 4  | 기술 개념이 대부분 정확하게 설명됨         |
| 5  | 기술 개념이 완전히 정확하며 예외 상황까지 고려됨 |

### depth (기술적 깊이) — technical 전용

| 점수 | 기준                                  |
|----|-------------------------------------|
| 1  | 표면적인 키워드 나열에 그침                     |
| 2  | 기본 개념 설명은 있으나 깊이가 없음                |
| 3  | 개념 설명은 충분하나 트레이드오프나 내부 동작 설명이 부족함   |
| 4  | 트레이드오프, 대안, 내부 동작 중 하나 이상을 언급함      |
| 5  | 트레이드오프, 실제 적용 경험, 개선 방향까지 포함한 심층 답변 |

### authenticity (진정성) — personality 전용

| 점수 | 기준                                |
|----|-----------------------------------|
| 1  | 경험 없이 추상적이거나 교과서적인 답변만 함          |
| 2  | 경험을 언급하나 구체성이 부족하고 진정성이 느껴지지 않음   |
| 3  | 실제 경험을 바탕으로 답변하나 감정이나 맥락이 충분하지 않음 |
| 4  | 경험 기반의 구체적이고 진정성 있는 답변을 함         |
| 5  | 경험, 감정, 배운 점까지 포함하여 설득력 있게 전달함    |

### growth (성장 가능성) — personality 전용

| 점수 | 기준                            |
|----|-------------------------------|
| 1  | 회고나 성장에 대한 언급이 전혀 없음          |
| 2  | 결과 언급은 있으나 배운 점이나 변화가 불분명함    |
| 3  | 배운 점을 언급하나 구체적인 변화나 적용이 부족함   |
| 4  | 경험을 통해 무엇을 배웠고 어떻게 적용했는지 설명함  |
| 5  | 성찰과 성장 과정이 명확하고 앞으로의 방향까지 제시함 |

---

## null 처리 규칙

- `technical` 질문: `authenticity`, `growth` → `null`
- `personality` 질문: `accuracy`, `depth` → `null`
- `null` 항목은 점수 계산 시 제외한다.
- 점수 계산 시 유효한 항목의 weight 합계를 기준으로 재정규화한다.

## STAR 평가 적용 기준

STAR 평가는 모든 질문에 강제 적용하지 않는다.

### 적용 대상

- 인성 질문
- 경험 기반 질문
- 프로젝트 경험 질문
- 상황 대처형 질문
- 기술 질문 중 실제 경험이나 프로젝트 수행 과정을 묻는 질문

### 비적용 대상

- 단순 기술 개념 설명형 질문
- 정의, 원리, 장단점 설명 중심 질문

예시:

- `RESTful API 설계 원칙에 대해 설명해주세요.` → STAR 비적용 가능
- `REST API를 설계하며 어려움을 해결한 경험을 설명해주세요.` → STAR 적용 가능
